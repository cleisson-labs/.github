# Contributing to Cleisson Labs

Use the affected repository's README for prerequisites, build commands and tests. Open an issue before changing a public interface or starting a substantial feature. For a small fix, a focused pull request is welcome.

1. Branch from the default branch and keep the change focused.
2. Reproduce the problem with a test or a small example. Include the operating system, tool versions and expected result.
3. Run the relevant checks locally and describe the results in the pull request. Update user-facing documentation when behavior changes.
4. Submit the pull request and resolve review comments. The required `ci-ok` check collects the repository's mandatory validation jobs.

Use synthetic configuration and redact credentials, private paths and account data. Report vulnerabilities privately using the affected repository's Security tab. Contributions follow the license of the repository receiving them.
